Given the assumptions in Problem 6.38, determine the cache performance of the
following code:

for (i = 15; i >= 0; i--) {
    for (j = 15; j >= 0; j--) {
        square[i][j].y = 1;
    }
}
for (i = 15; i >= 0; i--) {
    for (j = 15; j >= 0; j--) {
        square[i][j].c = 0;
        square[i][j].m = 0;
        square[i][j].k = 0;
    }
}


A. What is the total number of writes?
16 * 16 * 4 = 1024 (same)


B. What is the total number of writes that hit in the cache?
first loop:

    there can't be a hit, since a single element takes up a whole block,
    the cache is empty and each one will be accessed once

    16 * 16 = 256 writes
    0 hits

second loop:

    previously loaded values will be useless, since the cache will hold the first fourth of the 
    elements, but we need the last one, and the cache can only fit a fourth of the array at a time

    then, the first one will always be a miss, and the two following will hit

    16 * 16 * 3 = 768 writes
    768 * 2/3 = 512 hits


C. What is the hit rate?
256 + 768 = 1024 writes
512 / 1024 * 100 = 50% hits
